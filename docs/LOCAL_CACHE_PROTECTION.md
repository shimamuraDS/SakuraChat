# Windows 本地聊天缓存保护

## 已实施的范围

消息表 `messages.payload` 与联系人表 `contacts.payload` 现在写入 Windows DPAPI 密文。密钥由 Windows 用户配置管理，应用不在 config.ini、数据库或 Git 中保存解密密钥。使用用户范围 DPAPI，不使用允许所有本机用户解密的机器范围标志。

保护上下文包含网关环境摘要、聊天账号 UID、记录类型和主键。将某条密文直接搬到其他主键、账号或环境时不能正常解密。该机制保护正文/资料内容，不认证整个数据库的结构或查询列。

**不是 SQLCipher，也不是整库加密**。UID、消息标识、时间、序号、状态、未读数相关列、回执队列和同步游标仍为明文。云端服务器仍可读取聊天正文。当前只实现 Windows；不支持的平台不退回明文保存。

## 首次运行与旧数据

本次只编译代码，没有启动程序，也没有打开或迁移你的实际缓存。

在运行新版本前，请退出所有客户端，备份整个账号缓存目录（包括存在的 `chat.sqlite-wal` 和 `chat.sqlite-shm`），不要只复制一个正在使用的主数据库文件。缓存位于 Qt AppLocalDataLocation 下 `chat/<环境摘要>/<UID>/`。旧备份包含明文，须单独保护。

新版首次登录打开缓存时：

1. 检查 `local_security` 版本及受 DPAPI 保护的验证数据；解密失败直接拒绝打开。
2. 对尚未转换的库，按每批 100 行读出旧消息和联系人，再保护 payload；全部批次和版本标记在一个事务中提交。
3. 任一转换错误则回滚，不清空记录；成功后，新写入只保存密文，不再接受明文 payload 作为读取回退。

转换当前仍在 GUI 线程进行，记录很多时首次登录可能等待较久；分批限制内存，不代表后台迁移。仅编译通过，尚未验证转换中断、磁盘不足、多进程竞争等场景。

**转换后不要用旧版客户端打开该缓存。** 旧版不理解密文，可能写回不兼容记录。需要回退时先停止全部客户端，并使用升级前的完整备份，不要混用新旧 WAL。

## 无法解密时

正常情况下依赖原 Windows 用户及相应 DPAPI 用户配置；复制数据库到另一台电脑或另一 Windows 用户不保证可解密。重装系统、丢失用户配置、管理员重置系统密码等情况可能影响恢复。聊天账号改密和 Windows 凭据不是同一件事。

出现解密错误时保留完整缓存，不自动删除、不自动重建、不以空记录覆盖。服务端已有的云端消息可在正常账号访问下重新同步；只存在本地的未发送草稿/消息不能保证通过云端恢复。当前未提供跨机密钥导出与加密备份工具。

运行中读取损坏的密文会停止仓库后续读写，并向界面报告错误。不要把解密失败当成磁盘空间不足。

## 仍然存在的边界

- 相同 Windows 用户权限下的其他程序可能调用 DPAPI；不防管理员、进程调试、内存抓取、已解锁桌面上的恶意代码。
- 解密后的消息仍进入进程内存和 UI。应用锁不提供独立的磁盘解密密钥。
- 开启 SQLite secure_delete 只是有限清理措施；旧 WAL、空闲页、备份、文件系统快照、SSD 残留和分页文件可能仍有历史明文。未执行 VACUUM、删除备份或安全擦除，不承诺既有明文已彻底消失。
- 本地明文查询列仍可被有写权限者篡改；这不是整个数据库的防篡改签名。安全消息授权仍须由服务器执行。
- 生产环境仍需要操作系统账户保护、磁盘加密、备份保留策略及运行验证。

接口依据：[Microsoft CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)、[CryptUnprotectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptunprotectdata)。
