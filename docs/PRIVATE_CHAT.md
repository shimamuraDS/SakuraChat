# 隐私对话模块

## 边界

隐私对话沿用账号标识，但不沿用普通聊天的正文接口和历史存储。协议库通过项目定义的 C ABI 供 C++ 调用；QML、网络层和数据库不参与实现密码算法。

| 模块 | 职责 |
| --- | --- |
| `crypto/signal-bridge` | 调用官方 libsignal：身份、一次性预密钥、会话、安全码、加解密 |
| `src/privatechat/signalbridge.*` | 从应用目录加载 DLL，校验 ABI，管理返回缓冲区 |
| `src/privatechat/privatechatstore.*` | 独立 SQLite，DPAPI 保护状态，事务保存会话与密文发件箱 |
| `src/privatechat/privatechattransport.*` | 账号鉴权的 HTTPS 密文传输，拒绝私钥/状态字段、重定向和远程明文 HTTP |
| `src/privatechat/privatechatengine.*` | 工作线程上的协议调用、身份存储及收发事务，不向 UI 返回私钥 |
| `src/privatechat/privatechatcontroller.*` | 登录生命周期、安全码核验、预密钥发布、离线密文轮询及重试 |
| `qml/ChatDialog.qml`、`ConversationInfo.qml` | 共用聊天布局，按模式选择数据源，提供可选安全码核验入口 |

协议依赖固定到官方 libsignal 提交 `8fc2113bda042fc972a166a24b974b0d34155c6c`，传递依赖由 Cargo.lock 固定。协议库的第三方使用不受 Signal 官方支持；升级必须重新执行协议与 ABI 测试。

## 状态及安全约束

- 桥接 ABI 的 JSON 是进程内序列化边界，包含私钥，绝不能发送到服务器或放入日志。
- 所有操作从持久状态生成候选新状态，失败不返回候选状态。发件箱与新协议状态必须同事务提交，提交成功后才可发送；重试发送保存的密文，不重新加密同一消息。
- 存储对账号和服务环境进行绑定；无法解密时拒绝打开，不自动重建身份。使用已读取状态的比较更新，拒绝陈旧写入。
- 首次使用对方身份时自动保存（TOFU），可以直接加密聊天，但显示“身份未核验”。通过可信渠道比较完整安全码并明确确认后，才标记“已核验”。已保存的身份变化时暂停发送，不自动替换；新身份需重新核验确认。安全码采用 libsignal 的指纹接口。未核验时无法排除首次连接遭身份冒充的风险。
- 接收首条消息时，首次身份保存与成功解密的消息在同一事务中提交；篡改或验证失败的消息不会建立持久信任。旧状态中未记录人工核验标记的身份显示为未核验。
- 当前协议地址使用单设备 ID 1，正式设备注册层必须禁止同一账号的不同设备覆盖对方身份。
- 预密钥采用一次性 EC 和 Kyber 密钥；消费状态随会话事务保存。预密钥池设上限，补充和旧签名密钥清理必须由设备服务管理，不能无限增长。
- 状态加密防止直接读取数据库，不保证抵抗已控制用户会话的恶意程序或旧磁盘快照回滚。

## 构建和测试

需要 Rust 1.98.1（MSVC x64）、Visual Studio C++ Build Tools、protoc、Qt 6.8 的 MinGW 开发环境。Rust DLL 与 MinGW 主程序只通过 C ABI 交互，不跨边界传递 C++ 对象或分配器。

先用 Qt Creator 配置客户端 CMake，然后运行：

```powershell
./tools/build-private-chat.ps1 -BuildDirectory '<客户端构建目录>' -QtBin '<Qt bin目录>'
```

可用 `-Cargo` 和 `-CMake` 指定工具路径。首次构建需要下载依赖。普通客户端构建不自动下载或安装工具链。

测试覆盖：双方建会话和安全码一致、序列化恢复、乱序、重放、密文篡改、身份变化、无效 ABI 输入、C++/Rust 调用、密钥落盘保护、发件箱事务和陈旧写入拒绝。

`privatechatengine_tests` 在临时目录运行两个独立客户端引擎，覆盖双向正文收发、上传待确认预密钥恢复、未知身份拒绝、消息编号与加密正文绑定、失败接收不推进会话、重启去重、确认后清理发件箱，以及失败账号切换后的隔离。这是客户端集成测试，不替代真实 GateServer/MySQL 联调。

服务端的 `privatechat_database_tests` 另行覆盖回环 HTTP → 生产鉴权处理器 → 隔离 MySQL 的密文收发链路；其令牌和限流依赖使用受控夹具，不代表真实 Redis 和两个 QML 客户端的完整联调已经完成。

`privatechat_e2e_tests` 配合服务端 `tools/test-private-chat-e2e.ps1`，使用两个独立的正式客户端引擎和网络模块，通过真实 GateServer 路由、真实 Redis 以及隔离 MySQL 验证双向 Signal 加密收发、重复提交、取件确认和重新打开本地会话后的回复。测试不自动点击 QML 页面；账号会话由隔离夹具预置，注册/登录和生产 TLS 代理不在此测试范围内。

## 集成状态

后台连接错误显示在独立状态区，不覆盖安全码核验提示。请求受限时遵守服务端冷却时间；临时连接故障使用指数退避。冷却期间禁用手动重试，切换模式不能绕过冷却，退出账号会取消重试。所有发送重试复用已保存的请求和密文。`privatechatcontroller_tests` 验证提示隔离、冷却、模式切换、成功恢复及退出取消行为。

登录成功后，可从标题栏切换到“隐私对话”。两种模式共用侧栏、会话列表、消息气泡、输入框和详情布局：普通模式为蓝色，隐私模式为黑金色并显示锁标识。好友列表沿用同一账号，但消息记录、发送接口和状态独立，普通历史不会出现在隐私模式。首次启用会注册本设备身份并补充预密钥；选择好友后首次信任其身份，可直接加密发送。标题栏的“安全码”或详情中的“查看安全码”可打开可选核验弹窗。已有有效会话会复用，身份变化时阻止自动替换；明确核验新身份后才清除对应旧会话并重新建立。

接收端将解密正文和新协议状态一起加密保存到独立 SQLite 后才确认收件。确认响应丢失时根据已保存的接收记录去重。发件箱在服务器确认之前保留同一密文，状态仅为“等待提交”或“服务器已接收”，不提供已读回执。本机页面显示每位联系人最近 200 条记录。退出账号关闭存储，重新登录不会主动删除记录。

部署前需要构建并放置桥接 DLL，手动执行服务端 `006_private_chat.sql`，更新 GateServer 并配置 HTTPS 网关（仅本机开发允许 HTTP）。自动化验证覆盖客户端核心模块、真实 HTTP 鉴权链路和隔离存储，不等于完成生产安全审计或所有界面验收。没有多设备、密钥恢复及完整的旧签名预密钥清理机制；当前预密钥记录上限为 100，启动时补足 10 个可领取密钥，达到容量限制会失败而非丢弃解密所需密钥。单个加密协议状态受本地保护模块 1 MiB 限制。
