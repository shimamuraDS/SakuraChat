# 聊天记录与已读状态使用说明

## 启动

1. 先更新并启动协议版本 2 的 ChatServer 两个实例。数据库前提见服务端 docs/CHAT_HISTORY_READ_RECEIPTS.md。
2. 重新加载客户端 CMake，构建 appSakuraChat；新增 Qt6::Sql 依赖，需要 Qt SQLite 驱动。
3. 在 Qt Creator 中使用现有 Qt 6.8.3 MinGW 套件启动。打包到其他机器时使用同一 Qt 套件的 windeployqt，确保包含 Qt6Sql.dll 以及 sqldrivers/qsqlite.dll；不能只复制 EXE。
4. 登录后自动恢复本机缓存并补拉服务端历史。左侧箭头按钮退出登录；退出保留记录，清除当前界面内容和草稿。

## 数据放在哪里

服务器 MySQL 保存已接受的消息。客户端使用 `QStandardPaths::AppLocalDataLocation/chat/<网关URL的SHA256>/<UID>/chat.sqlite` 保存消息、联系人、同步游标和待提交回执。

以网关地址区分环境，不以某个 ChatServer 节点地址区分；因此登录被分配到另一聊天节点不会切换本地数据库。修改网关地址视为切换环境，本机旧缓存仍保留。

本地 SQLite 默认为明文，不保存密码或 Token。退出登录不是删除记录；删除本地文件会丢失尚未被服务器接受的待发送消息，不要把删除缓存当作普通排错步骤。历史上已经清掉且从未持久化的消息无法恢复。

## 状态含义

| 显示 | 含义 |
| --- | --- |
| 发送中… | 本地已保存，正在等待服务端回应 |
| 已发送 · 未读 | MySQL 已提交，尚无已读回执 |
| 已送达 · 未读 | 接收客户端保存后提交了回执 |
| 已读 | 接收客户端前台可见后提交了回执 |
| 正在确认发送结果… | 超时/断线，尚无法确认结果 |
| 发送失败 | 服务端明确拒绝 |

未读准确含义是未收到已读回执。已读状态前台每两秒轮询一批四条，队列繁忙时更慢，不是即时推送。

回执发送失败或超时后保留在本地队列，退避 30 秒再尝试；期间允许历史补拉和状态查询继续，避免回执持续失败阻塞整个同步流程。

unknown/failed 气泡提供重试。重试沿用原 UUID 与正文，服务端做幂等检查，不能以新 UUID 盲目重发。新正文应当作为一条新消息发送。迟到成功回包和历史补拉会更新原气泡，不生成重复气泡。

## 实现位置

- src/chatrepository.*：SQLite，账号隔离、去重合并、回执队列、游标。
- src/chatstore.*：QML 数据投影、会话打开、200 条内存显示窗口（不是数据库删除上限）。
- src/tcpmgr.*：发送超时、代数隔离、历史补拉、状态轮询、退出登录。
- qml/ChatView.qml：前台可视停留判读、状态变化不强制滚到底部、历史加载。
- qml/MessageBubble.qml：状态文字与重试按钮，和时间分开展示。

本版 SQLite 操作在 GUI 线程内串行执行，查询和网络页有界；初次同步大量历史可能影响流畅度，后续可迁移到专用数据库工作线程。未实现多设备逐设备回执、离线自动重连、端到端加密或完整消息管理。

没有运行测试/启动应用或执行服务端 SQL，只进行了构建和静态核对。
