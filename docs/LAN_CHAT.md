# 加密局域网对话

左上角 Logo 旁的模式菜单可以切换默认云端对话和局域网对话。隐私对话入口禁用。

## 使用

1. 两台电脑连接同一可信局域网，打开客户端，无需登录。
2. 切换至局域网对话，填写昵称。房主点击创建房间，默认 TCP 端口为 45455。
3. 房主通过当面或可信渠道提供完整 SHA-256 证书指纹和邀请口令。其他成员填写真实网卡 IPv4、相同端口、指纹、口令和昵称后加入；不要从未经验证的网络提示复制指纹。
4. Windows 防火墙若提示，房主只允许可信的专用网络访问。不要关闭整个防火墙或配置公网端口转发。
5. 每条消息发送给房间所有成员。房主离开或关闭应用后房间关闭。

有多个地址时选择双方所在网段对应的网卡地址。访客 Wi-Fi 的客户端隔离可能阻止连接。同机调试可使用 127.0.0.1；多个房间需使用不同端口。

所有设备需要 Qt TLS 运行库。房主还需 OpenSSL 3 可执行程序及依赖，放在应用目录或加入 PATH。运行库缺失时创建失败，不会回退明文。每次创建房间生成新的 EC P-256 证书（有效期一天）和 128 位随机口令，需要重新分享。私钥通过子进程管道读取，不写入文件。请使用可信来源的运行库。

## 行为与边界

- 默认云端连接不因切换而退出，返回后恢复原页面；云端与房间消息独立。
- 切回默认模式会离开房间并清空内存记录。断线时保留可见记录，重新连接、主动离开和退出应用时清除。
- 仅文本群聊，最多 16 个成员连接（另加房主），最近 300 条内存记录，不写入数据库。
- TLS 1.2 或更高版本上的 JSON 换行分帧；正文最多 2000 UTF-8 字节，帧最多 8192 字节，连接发送积压限制为 64 KiB，每连接每秒最多 20 帧。
- 客户端必须匹配完整 SHA-256 指纹，仅对匹配证书处理自签名和主机名不匹配，其他证书错误拒绝。只有 TLS 核验成功后才发送口令，认证成功后才允许消息收发。
- 8 秒未认证的连接断开。同来源 IP 累积 5 次未成功认证的连接后本房间拒绝该 IP，认证成功重置其计数；来源表最多 256 项。重建房间重置计数和凭据。这些限制不保证抵御所有拒绝服务攻击。
- 仅接受私有/链路本地/回环 IPv4 地址。地址范围检查不是身份认证或可靠的网络安全边界。
- TLS 保护成员与房主之间的传输，房主可以读取并转发消息；昵称未经实名验证，口令持有者可自行选择昵称。没有成员间端到端加密、已读回执或离线投递。回显表示房主已接收，不表示其他成员已读。
- 不记录口令或正文日志，不承诺操作系统交换文件或内存转储中的安全擦除。

## 验证

构建目标 `lanchat_tests`，运行生成的测试程序。覆盖 TLS 双客户端转发、错误指纹、错误口令、明文拒绝、多行消息、半包/合包、超长正文、非法数据、房主退出及离开清空。跨机器仍需验证实际网络、防火墙和目标机器 TLS 运行库。

TLS 行为参考 [Qt QSslSocket 文档](https://doc.qt.io/qt-6/qsslsocket.html)。
