# 消息删除与事件同步

客户端已识别 1046/1047 删除事件接口：约每 10 秒轮询当前账号，分页同步删除标记。SQLite 的 local_deleted 保存 sender/msgid，删除游标使用 sync_cursor 的保留键 peer=0；删除消息、清理回执、记录标记与推进游标在一个事务中完成。

历史同步、迟到通知和重试的合并入口检查该标记，不将已删除消息重新写回缓存。消息正文从当前缓存行删除，不代表从 WAL、旧备份或物理磁盘安全擦除。

已增加消息下方的“删除”按钮与二次确认。默认仅从自己的账号删除；自己的消息可选择“同时为对方删除”。只有已获得服务器 message_id 的消息支持该操作，未发送或发送结果未确认的消息暂不支持。

1044/1045 请求带 UUID 关联，单次等待最多 8 秒。等待中禁止重复点击；超时提示结果未知，继续轮询事件，可稍后重新确认。只有服务端确认后才移除本地消息，本地事务失败另行提示，不把“服务器删除成功”说成“本地也已删除”。删除回包不推进事件游标；应用锁禁止发起新删除请求。

服务端须先备份并手动执行 database/004_message_deletion.sql；本次未执行迁移或运行界面/接口测试。功能已接线，运行效果尚未验证。

多设备同时在线尚未实施；这里的跨端指同一账号在其他客户端重新登录后同步删除记录。离线客户端获知删除前仍可能展示旧缓存，已导出数据和截图不能远程擦除。
